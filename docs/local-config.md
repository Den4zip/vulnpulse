# Локальная конфигурация стека ПО

Пример: [local-stack.example.json](../examples/local-stack.example.json). Это демонстрационный инвентарь из четырёх компонентов, а не рекомендуемые версии для установки. Замените компоненты и версии данными своего контура.

В собранном приложении выберите **Данные → Загрузить локальную конфигурацию ПО…**, затем JSON-файл. Окно результата покажет число добавленных, уже существующих и всех сохранённых компонентов. Данные хранятся в локальной SQLite профиля Electron. Этот импорт не обращается к сети. Таблица и CRUD доступны в [Стек ПО](stack-ui.md); автоматический запуск matcher ещё не подключён. Импорт также доступен из Стек ПО → Импорт JSON.

Конфигурация ПО добавляет компоненты в стек; каталог «Уязвимости» и его показатели заполняются отдельным импортом OSV JSON / XML БДУ ФСТЭК или загрузкой фидов. Для проверки каталога можно импортировать [osv-demo.json](../examples/osv-demo.json) через кнопку «Импорт → OSV JSON». Сохранённые ранее компоненты отображаются в разделе «Стек ПО» без повторного импорта; поиск, формы и удаление работают через Main/IPC.

## Формат v1

UTF-8 JSON (BOM допустим), до 4 МиБ, объект с `schemaVersion: 1` и массивом `components` от 1 до 1000 элементов. Неизвестные поля отклоняются: файл не предназначен для ключей API, настроек источников или записей уязвимостей.

| Поле компонента | Правило |
| --- | --- |
| `kind` | `application`, `system` или `package` |
| `name` | Название для пользователя |
| `vendor` | Необязательно для PURL; обязательно и должно совпадать с vendor CPE при `cpe23` |
| `product` | Продукт CPE или canonical name PURL: `lodash`, `django`, `org.apache.logging.log4j:log4j-core` |
| `version` | Конкретная установленная версия, строка. Диапазоны и `*` не принимаются |
| `purl` | npm/PyPI/Maven с той же версией и canonical name; без qualifiers/subpath |
| `cpe23` | CPE 2.3 с конкретными vendor, product, version, совпадающими с отдельными полями |

Нужен хотя бы один из `purl`/`cpe23`. Строки непустые, до 2048 символов, без управляющих символов и пробелов по краям. Отсутствующие необязательные поля и `null` равнозначны. Формат намеренно ограничен поддерживаемым инвентарём; это не SBOM CycloneDX/SPDX и не конфигурация API.

Импорт добавляет записи. Идентичность — точная тройка `vendor/product/version` (отсутствующий vendor учитывается как NULL). Повтор той же записи пропускается без изменения ID и дат. Другая версия добавляется отдельно; отсутствие компонента в файле не удаляет существующий. Отличающиеся метаданные при той же тройке, дубликаты внутри файла или некорректная запись отклоняют **весь** импорт. Существующие записи и связанные данные не перезаписываются. Редактирование/замена инвентаря этим форматом не выполняются; для изменения компонента используется форма раздела «Стек ПО».

## Проверка

После `npm run build`: `npm run e2e -- tests/e2e/local-config.spec.ts`. Тест запускает настоящий собранный Electron с отдельным временным профилем, проверяет окно/preload, изоляцию, импорт примера через обработчик меню, повтор, атомарный отказ при конфликте, отмену выбора и сохранность после перезапуска. Только системные диалоги в тесте подменяются для воспроизводимого выбора пути; работа самого Windows file picker этим тестом не подтверждается.

Unit-тесты `tests/unit/stack-config.test.ts` дополнительно проверяют лимиты, неверный UTF-8, отсутствующий файл, отмену, ошибки CPE/PURL и NULL-safe идемпотентность. Команды общей проверки: `npm run typecheck`, `npm test -- --coverage`, `npm run build`.
