# Настройки и ключ NVD

Реализовано и проверено 2026-11-07, четвёртый пункт стадии 6. Сервис Main хранит обычные настройки отдельно от OS-encrypted ключа. Settings-экран React ещё не реализован; API доступно через preload, расписания также меняются через меню Данные.

## API и расписания

| Метод `window.electronAPI.settings` | Действие |
| --- | --- |
| `get()` | revision, настройки фидов, readonly osvMode и безопасное состояние ключа |
| `update({ expectedRevision, feeds })` | Полностью заменить настройки трёх сетевых источников |
| `setNvdApiKey({ expectedRevision, apiKey })` | Зашифровать и сохранить ключ |
| `removeNvdApiKey({ expectedRevision })` | Удалить ключ, сохраняя историю его ревизии |

Read/command DTO в shared/api.ts независимы от Main/Electron/Drizzle. Все методы возвращают ApiResult через прежний guard окна/frame/origin/URL. Ошибки async safeStorage/SQL обрабатываются тем же безопасным транспортом, что и синхронные сервисы; исключения/SQL/config/ключ не попадают в ответ.

`feeds` содержит только cisa/nvd/fstec, для каждого обязательны enabled:boolean и intervalMinutes:integer. Политика интервалов:

| Источник | Default | Минимум / максимум, минуты |
| --- | --- | --- |
| CISA KEV | 60 мин. | 60 / 10 080 |
| NVD | 120 мин. | 120 / 10 080 |
| ФСТЭК, неофициальное зеркало GitHub | 1440 мин. | 1440 / 43 200 |

Новая база создаётся со всеми enabled:false. Явно включённые источники и интервалы теперь сохраняются между запусками. При включении или старте просроченный включённый источник догружается через существующий scheduler, с учётом последней попытки/интервала. Menu → «Автообновление (сохраняется)» использует тот же сервис и показывает действующий интервал. Это заменяет прежние переключатели на одну сессию.

Ручная загрузка по-прежнему может запускаться при выключенном автообновлении. Глобальный переключатель запрета сети этим пунктом не добавлен. OSV остаётся локальным: osvMode='local-json', включить querybatch или поменять endpoints через настройки нельзя. Значение enabled для ФСТЭК относится именно к неофициальному зеркалу.

Настройки имеют собственную revision. Передаётся значение из get; устаревшее даёт CONFLICT. Весь feeds заменяется атомарно; неполные/лишние поля, OSV, неправильные числа/boolean и превышение интервалов отклоняются. Повреждённые сохранённые настройки не сбрасываются молча в defaults.

## Хранение ключа

`settings.value_json` содержит только version/feeds; `app_secrets.ciphertext` — BLOB из Electron safeStorage. Миграция 005 создаёт эти две таблицы; сервис один раз создаёт default singleton/пустую запись ключа. Прежние данные и миграции не переписаны. История ключа сохраняется в отдельной revision: удаление ставит ciphertext=NULL и повышает её, поэтому старый запрос после delete/recreate отклоняется.

Renderer отправляет ключ только при явном сохранении и никогда не получает его обратно. В get возвращаются только:

- revision ключа, configured и storageAvailable;
- status missing/available/unavailable — отсутствие, возможность расшифровки, недоступность;
- needsReencrypt — сигнал safeStorage о необходимости повторного шифрования при ротации OS key provider.

`available` означает успешную расшифровку, не проверку ключа на живом NVD. Допустимы 1..256 видимых ASCII символов без пробелов/controls; конкретный формат ключа поставщика не угадывается. Маски/последние символы/шифротекст в read DTO не возвращаются.

Используются асинхронные API Electron 45: isAsyncEncryptionAvailable/encryptStringAsync/decryptStringAsync; SQLite-транзакция не удерживается во время OS work. Нет plaintext fallback. Linux basic_text/unknown отклоняются; допускаются проверенные имена Secret Service/KWallet backend. При недоступной защите или ошибке шифрования сохранение отклоняется с UNAVAILABLE, прежний ключ остаётся. Повреждённый/чужой шифротекст остаётся недоступным; удалить его можно без расшифровки.

NVD получает ключ через отдельный Main-only метод перед запуском адаптера. Если ключ отсутствует — прежний анонимный режим. Если он настроен, но не расшифровывается — sync завершается ошибкой до HTTP, без тихого перехода в анонимный режим. Rate-limit бюджеты адаптера общие и не сбрасываются при его создании для нового запуска. Новые запросы идут только через HttpClient.

Все изменения настроек/ключа получают BUSY во время активного sync/локального импорта или другой записи настроек. Планировщик тоже не начинает новую загрузку во время OS encryption. После успешной записи настройки применяются к runtime; при выходе приложение ждёт незавершённую запись и только затем закрывает SQLite. ОС-ошибки и observer errors не логируют credentials. Чтение настроек может вернуть более ранний snapshot при параллельном изменении; его ревизия остаётся обязательной для следующей записи.

Шифруется только credential, не вся SQLite. На Windows safeStorage использует DPAPI; перенос/доступ из другого OS-контекста не гарантируются. Автоматическое перешифрование при needsReencrypt пока не выполняется: флаг доступен клиенту, последующее явное сохранение ключа шифрует заново. Linux/macOS runtime этим этапом не проверены.

## Фактические проверки

- Typecheck и production build успешны. Dependencies не менялись, рабочая пользовательская БД не открывалась.
- Полный Vitest+coverage: **816/816**, 28 файлов (+42 settings/vault, +1 migration, +1 IPC, +1 scheduler case; прежние тесты адаптированы к сохранению флагов и пятой миграции). Settings: 96,42% statements / 92,75% branches / 100% functions/lines; vault — все 100%. Matcher — все 100%. Общие services: 87,62% / 85,91% / 94,80% / 90,59%. Scope coverage прежний: services, без инструментации IPC/preload и собранного XML worker.
- Unit использует тестовый криптопровайдер, SQLite и реальные сервисы: отсутствие plaintext, stale/ABA, unavailable/basic_text, повреждение ciphertext, лимиты, rollback, busy и ожидание OS work при shutdown. Отдельная миграция сохраняет заполненные notes/SLA revisions, статус, ETag/checkpoint, проходит повтор/FK check.
- Полный Electron E2E: **8/8**, 6,8 с; новый settings-сценарий 2,8 с. Настоящий Windows safeStorage, отдельный профиль, сохранение и расшифровка после restart, только metadata в Renderer/только ciphertext в SQLite; ключ приходит в заголовок NVD из Main. Повреждение шифротекста блокирует HTTP, удаление восстанавливает анонимный режим. Также проверены настройка интервалов/меню, persisted opt-in, BUSY и отказ всем четырём методам другому окну. Native result dialogs и Axios transport подменены; реальный Node HTTP/HTTPS заблокирован. Live NVD и валидность настоящего ключа этим не проверяются.
- Первые и финальные целевые прогоны успешны; отдельный audit, нагрузка/установщики/backup не выполнялись. Нативная защита Windows проверена, остальные платформы — только кодовые/модульные условия.

API и семантика safeStorage сверены через Context7 `/electron/electron`, [официальную документацию](https://www.electronjs.org/docs/latest/api/safe-storage), установленные типы Electron 45.0.0 и реальный runtime. Отдельного снимка 45.0.0 в Context7 нет; синхронные deprecated методы не используются.
