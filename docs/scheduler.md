# Планировщик фидов

Реализовано и проверено 2026-11-07. Main создаёт один `FeedScheduler` на соединение SQLite. `node-cron@4.6.0` проверяет просроченные задания каждую минуту в UTC; после выхода из приложения расписания не работают.

## Управление через меню Данные

- **Обновить CISA KEV сейчас / Обновить NVD сейчас** — однократная загрузка. Первый запуск NVD получает весь каталог и может быть долгим. Ключ теперь берётся из [Settings](settings-api.md) только в Main; недоступный сохранённый ключ блокирует запрос.
- **Загрузить ФСТЭК из зеркала…** — прежняя команда, теперь через тот же планировщик и учёт запусков. Источник — неофициальное зеркало GitHub.
- **Автообновление (сохраняется)** — отдельные переключатели источников. В новой БД все выключены; явно сохранённое включение восстанавливается при старте. Просроченный включённый источник загружается сразу; если занят импорт/запись Settings, он ждёт минутной проверки.
- **Отменить текущую загрузку** — отмена сетевого задания или локального импорта.
- **Состояние обновлений** — источник, флаг автообновления, состояние, начало и конец последнего сетевого запуска в UTC.

| Источник | Интервал по умолчанию от конца предыдущей попытки | Получение |
| --- | --- | --- |
| CISA KEV | 1 час | Общий каталог, ETag/304 |
| NVD | 2 часа | Начальный каталог, затем существующие инкременты/checkpoint |
| ФСТЭК | 24 часа | XML.GZ из неофициального зеркала, ETag/304 |
| OSV | Нет сетевого расписания | Только прежний локальный JSON-импорт |

После ошибки/отмены повтор — не раньше `max(интервал источника, 5 минут)`. Ручной запуск обходит интервал, сохраняя блокировку и HTTP-лимиты. Сохранённые интервалы меняются через Settings API, меню показывает действующие значения. Пропущенные интервалы сворачиваются в один запуск. Это заменяет прежние сессионные переключатели.

## Состояние и сохранность

Состояние сетевых запусков использует существующие поля `feeds`. Сохранение настроек добавлено отдельно миграцией 005, см. [Settings](settings-api.md):

- `last_started_at` — начало попытки, ISO UTC.
- `last_finished_at` — конец этой попытки, включая ошибку/отмену; при старте очищается. Это не время последней успешной загрузки.
- `last_error` — `NULL`, `failed` или `cancelled`. Исключения и payload не сохраняются в поле или логах планировщика.

Сохранённое начало без конца (либо начало позднее конца) даёт состояние `interrupted` и повтор после включения источника. Это вывод из последних отметок; отдельной истории `sync_runs` пока нет. Локальные OSV/XML-импорты не учитываются как сетевые запуски.

Адаптеры продолжают владеть ETag, транзакциями и checkpoint: планировщик их не переписывает. `304` считается успешной проверкой. У NVD применённые страницы сохраняются после сбоя/отмены, а незавершённое окно перечитывается; ошибка не объявляется полным успехом. Отмена после успешного коммита не превращает его в откат. Синхронный SQLite commit всё ещё может блокировать Main.

Все сетевые задания сериализованы и не пересекаются с локальным импортом/выбором файла. Занятое задание пропускается без очереди и проверяется позднее. Отключение активного источника отменяет его. Выход останавливает cron, передаёт отмену, ждёт завершения адаптера/worker/импорта и затем закрывает SQLite. `requestSingleInstanceLock()` не допускает второго экземпляра того же профиля.

Синхронизация и импорт доступны через [IPC API](sync-api.md): запуск с ID операции, status и адресная отмена; меню/cron/API используют те же блокировки. Автоматический пересчёт matcher, сохранение assessments, подробный прогресс и UI впереди. Начальный NVD-каталог и неофициальное зеркало не гарантируют полноту или актуальность всех данных.
